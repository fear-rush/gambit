## Project Overview

**Gambit** is a real-time crypto trade aggregator — a full-stack TypeScript monorepo with three workspace packages:

- **client/** — React 19 frontend (Vite, TanStack Router, TanStack Query, Tailwind CSS v4). Thin display layer that connects to server WebSocket.
- **server/** — Bun server running exchange adapters, trade aggregation, and WebSocket broadcast. Connects directly to exchange WebSockets.
- **shared/** — Shared TypeScript types imported by both client and server.

## Architecture

### Data Flow
```
Exchange WS → [Server: Exchange Adapters → Aggregator]
  → ServerWebSocket broadcast → Client WebSocket → React UI
```

### Monorepo Orchestration
- **Bun** is the package manager and runtime (v1.2.4)
- **Turbo** orchestrates tasks across workspaces with dependency-aware caching
- `postinstall` automatically builds `shared` and `server` so types are available immediately

### Type Sharing
Shared types live in `shared/src/types/index.ts` and are re-exported from `shared/src/index.ts`. Both client and server import them as `import type { ... } from "shared"`. Path aliases are configured in the root `tsconfig.json`: `@server/*`, `@client/*`, `@shared/*`.

### Server Architecture
- **Vanilla `Bun.serve()`** in `server/src/index.ts` — no framework.
- Server runs 27 exchange adapters (`server/src/exchanges/`) that connect to exchange WebSockets directly.
- **Aggregator** (`server/src/aggregator.ts`) processes trades and broadcasts `AggregatorPayload` JSON to connected clients.
- Endpoints:
  - `/ws` — Aggregator WebSocket stream (clients connect here for live trade data)
  - `/ws-proxy` — Generic WebSocket proxy (pass `?target=<url>`)
  - `/api/products` — REST endpoint returning all exchange products for search
  - `/health` — Health check
- Auto-connects to default markets (`BINANCE:btcusdt`, `BITSTAMP:btcusd`) on startup.
- Dev runs with `bun --watch` for hot reload.
- `server/tsconfig.json` has `strict: false` because exchange adapters use implicit any.

### Client Architecture
- **TanStack Router** uses file-based routing in `client/src/routes/`. The plugin auto-generates `client/src/routeTree.gen.ts` — do not edit this file manually.
- **TanStack Query** manages server state. QueryClient is created in `client/src/main.tsx`.
- **Tailwind CSS v4** via `@tailwindcss/vite` plugin. Styles in `client/src/index.css`.
- **Vite config** (`client/vite.config.ts`): TanStack Router plugin must come before the React plugin.
- `VITE_SERVER_URL` env var controls the API base URL (defaults to `http://localhost:3000`).
- **AggregatorService** (`client/src/services/aggregatorService.ts`) — WebSocket client that connects to server `/ws`, emits events via EventEmitter3.
- **ProductIndex** (`client/src/services/productIndex.ts`) — fetches product list from `/api/products` REST endpoint for search/filter UI.
- No Web Worker on client — all exchange processing happens server-side.

### Code Style (Biome)
- **Indent**: tabs
- **Quotes**: double quotes
- **Linter**: recommended rules enabled
- Biome handles both linting and formatting (single tool, no Prettier/ESLint)
- Exchange adapters (`server/src/exchanges/**`) have lint/format disabled (ported from aggr, non-standard style)

## React Best Practices

Follow `.claude/skills/vercel-react-best-practices` for all client code. This is a **Vite SPA — not Next.js** — so ignore the following categories that are Next.js/Vercel-specific:
- **`server-*` rules** (RSC, server actions, React.cache, after()) — we have no server components
- **`async-suspense-boundaries`** — no streaming SSR
- **`async-api-routes`** — no Next.js API routes
- **`rendering-hydration-*`** — no SSR hydration
- **`rendering-activity`** — experimental React API, not stable
- **`bundle-dynamic-imports`** using `next/dynamic` — use `React.lazy()` + `Suspense` instead
- **`client-swr-dedup`** — we use TanStack Query, not SWR

All other rules (re-render optimization, bundle size, JS performance, async patterns, rendering, advanced) apply directly.
